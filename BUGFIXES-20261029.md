# Android reliability fixes — 2026-10-29

The application version remains unchanged. These changes address B01–B14 in the read-only audit.

## Downloads and installation

- Validate HTTP 206, exact Content-Range and byte counts for every range. Fall back safely when a server returns a full HTTP 200 response.
- Structured download workers finish or cancel before staging files can be removed or published. Cancellation closes sockets and remains coroutine cancellation.
- Verify the music archive against its pinned SHA-256, not preallocated file length. Keep incomplete downloads in a separate staging file.
- Extract music into a temporary directory, validate the installed-file manifest, then replace the live pack. Failed reinstallations retain the previous resources.
- Adopt complete legacy music installations by checking the archive entry list and all extracted file sizes. Partial installations are not considered ready.
- Stage and verify all mod replacements before committing. Back up replaced/removed files, roll back failed commits, and recover interrupted commits from an on-disk journal before computing the next update plan.
- Process removal-only mod updates. Refuse empty/malformed manifests and missing required downloads instead of declaring success.
- Install the bundled, validated resource pack into the actual game version's resourcepacks directory; the old empty implementation is gone.
- Return the real CSV installation result. Persist validated CSV content atomically and only display success after installation.

## Chat and account boundaries

- Separate histories, indexes, cursors and pending ciphertext by relay and canonical account username.
- Copy legacy histories only when every message's sender/recipient/direction matches the current owner. Do not delete the original files or inherit the old global cursor.
- Serialize and atomically publish local message/index writes. Replayed message IDs do not increment unread counts twice.
- Persist undecryptable ciphertext before acknowledging a page. Retry it on subsequent synchronization instead of discarding it.
- Capture storage ownership for asynchronous results, clear identity/UI subscriptions on account changes, and reject delayed profile/authentication responses from a previous login.
- Preserve the existing device key pair for compatibility; scope ephemeral peer-key caches by account and relay.
- Use sender usernames, not display names or user-defined remarks, when loading chat-bubble avatars. Notify every waiting avatar view after a shared lookup.

## Playback, lifecycle and cache maintenance

- Subscribe screens independently to player state; home and audio controls no longer replace each other's callbacks.
- Bind home-card progress and controls only to its actual source. Recreating an Activity does not pause an already-playing song through a toggle call.
- Unregister frame callbacks and observers on lifecycle teardown. Remove invisible collapsed/expanded layers from hit testing.
- Include forum/GIF disk and memory caches in global cache clearing and disk-size reporting. Prevent in-flight loaders from immediately repopulating cleared cache generations.
- Correct avatar memory-cache units and discard results for views rebound to another URL.

## Regression coverage

`./gradlew :app:testDebugUnitTest assembleDebug`

- `UpdateRegressionTest`: staging failure, atomic publication, rollback, removal-only updates, interrupted/committed journal recovery, manifest validation and safe file names.
- `DownloadManagerTest`: valid ranges, HTTP-200 fallback, invalid ranges, truncated bodies and cancellation cleanup.
- `ChatStoreTest`: account/relay separation, duplicate replay, durable pending ciphertext, legacy ownership migration, captured asynchronous ownership and concurrent writes.

CI now runs the regression suite before APK distribution and uploads the test reports. These are JVM tests using temporary data and mocked Android contexts; they do not replace device UI regression testing or live-server integration tests.
